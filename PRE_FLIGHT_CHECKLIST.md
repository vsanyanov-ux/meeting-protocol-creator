# Финальный чек-лист перед выездом к заказчику (Pre-flight Checklist)

Этот документ содержит список критических проверок, которые необходимо выполнить на твоем сервере и ноутбуке перед демонстрацией или установкой системы у клиента.

---

## 1. Проверка контейнеризации и GPU (Battle Test)
*Выполняется на основном ПК (Сервере)*

- [x] **Полная пересборка**: Выполни `docker-compose down` и затем `docker-compose up -d --build`. Система должна подняться без ошибок.
- [x] **Проверка видимости GPU**:
    *   Выполни `docker logs mpc-backend`. Ищи строки о загрузке CUDA или добавлении DLL.
    *   Выполни `docker logs mpc-ollama`. Проверь, что в логах нет ошибок инициализации GPU.
- [x] **Тестовая транскрипция**: Загрузи короткое аудио. В диспетчере задач (вкладка GPU) должен быть виден скачок потребления памяти и нагрузки при работе Whisper.

## 2. Проверка сетевой доступности (Multi-user)
*Выполняется с ноутбука и других устройств в сети*

- [x] **Доступ к интерфейсу**: Введи в браузере ноутбука `http://<IP_СЕРВЕРА>:90`. Интерфейс должен открыться мгновенно.
- [x] **Авторизация**: Проверь, что пароль (`APP_PASSWORD`) принимается и сохраняется в браузере ноутбука.
- [x] **Проверка мобильной версии**: Зайди с телефона в ту же сеть Wi-Fi и открой адрес. Убедись, что интерфейс читабелен и удобен.

## 3. Стресс-тест многопользовательской системы
*Выполняется одновременно с сервера и ноутбука*

- [x] **Очередь задач**: Запусти загрузку длинного аудио с сервера, и сразу после этого — другого аудио с ноутбука. 
- [x] **Верификация**: Вторая задача должна встать в статус `В очереди GPU` и начать обрабатываться автоматически после завершения первой.
- [x] **Стабильность**: Убедись, что сервер не упал с ошибкой Out of Memory (VRAM).

## 4. Проверка сохранности данных (Persistence)
*Выполняется на сервере*

- [x] **Перезапуск контейнеров**: Выполни `docker-compose stop`, затем `docker-compose start`.
- [x] **История**: Зайди во вкладку «История» на ноутбуке. Все ранее созданные протоколы должны быть доступны для скачивания.
- [x] **Логи**: Проверь, что в папке `backend/logs` создаются файлы и они наполняются информацией.

## 5. Подготовка «Дистрибутива» для переноса
*Проверка содержимого папки перед копированием на флешку*

- [x] **Файлы конфигурации**: `.env` (с правильными ключами Яндекса и паролем), `docker-compose.yml`, `nginx.conf`.
- [x] **Скрипты-помощники**: `GET_SERVER_IP.bat`, `Запустить_СИСТЕМУ.bat` (если сделал).
- [x] **Документация**: `ENTERPRISE_README.md` (чтобы оставить IT-отделу).
- [x] **Модели (Опционально)**: Если интернет у заказчика плохой, убедись, что папки `ollama_data` и `models_cache` содержат скачанные модели (это сэкономит часы времени).

## 6. Аудит безопасности и приватности (Data Privacy)
*Критически важно для корпоративных клиентов*

- [x] **Анонимизация Langfuse**: Убедись, что в `.env` стоит `LANGFUSE_ANONYMIZE=true`. После тестового прогона зайди в Langfuse и проверь, что в `Generation` вместо текста написано `[DATA REDACTED]`.
- [x] **Чистота логов**: Открой `backend/logs/app.log` и убедись, что там нет фрагментов расшифровки или итогового протокола.
- [x] **Безопасность файлов**: Проверь, что после обработки аудиофайл удален из папки `uploads/`, а на диске остался только `.docx` протокол.
- [x] **Доступ к БД**: Убедись, что файл `status.db` не доступен "миру" через веб-интерфейс (Nginx должен проксировать только `/api/`).
